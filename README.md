**How do I interpret user needs and implement them into a program? How does creating “user stories” help with this?**  
Interpreting user needs comes from meeting with them and having an open discussion about what they are looking for. If they are unsure of what exactly they needs, it's okay to start with a light overview requirement and start from there. User Stories help by breaking down these requirements in to smaller tasks, and applying a set of acceptance criteria to each. This helps teams tackle tasks together, and move faster.
